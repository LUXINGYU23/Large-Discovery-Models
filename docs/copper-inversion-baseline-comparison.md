## 原始来源与复现范围

- [Wei 等的论文](https://doi.org/10.1016/j.cageo.2024.105779)：Knowledge-driven stochastic modeling of geological geometry features conditioned on drillholes and outcrop contacts。期刊卷为 2025 年 196；DOI/仓库引用包含 2024。访问到摘要与方法片段，出版商全文页面返回 403；不声称完成了全文所有实验或全部图表复现。
- [作者代码](https://github.com/xiaolongw1223/Knowledge-driven-stochastic-modeling)，固定 commit `94b8615bb2a9ca135583852a23ba114964a4b5af`。
- 重新克隆后，`level_set_mc.py`、`geo_stats.py`、`loss_functions.py` 和两个 3D `mcmc_main.py` 与用户 package 内文件逐字节一致。
- package 的 `run_3d_comparison.py` 单独记录 SHA256；它的 ACQ_MCMC 是 package 的增强基线，不称为论文原生方法。

本次运行三个基线：

1. `paper_mcmc`：直接调用作者 `mcmc_sampling_single_chain`，原 Gaussian 参数、max_step=1，钻孔温度 3、钻孔＋露头温度 20。
2. `MCMC`：直接调用 package `run_method`；原始温度 20。原 package 仅加载露头 case，适配器将数据加载替换为当前 case；钻孔版明确是同算法的任务扩展。
3. `ACQ_MCMC`：package 原生 Bayesian-ridge/LCB 筛选，batch=4、warmup=30、beta=.75，保留其提案与筛选逻辑。

未用新 agent 重新设计或调参这些基线；不调用旧 package 的 LLM controller。原论文还研究地质形态不确定性，本轮最小损失对比不评判其后验采样质量。

## 两条独立实验轨道

### A. 同一评分器、相同求解资源：`matched-120s-v2`

- 两个相同 3D case、原始测量与初始矿体。
- 三个传统基线与三个冻结 LDM 求解器，共六种方法。
- LDM 代码统一从各自**第 6 轮、25 次正式评分以内**选择；先冻结源代码 SHA，再运行复验。后续在线结果不会进入这次对比。
- 每种方法 seeds=47/48/49；每次同为 **2 CPU、4 GiB、120 秒硬上限、64 PID**；原始不可写输入、两项固定接口样例、原独立 scorer 保留。所有求解器使用同一个派生容器镜像，评分器使用原固定镜像。
- 基线内部调用同一 `objective_v1.score`，包含评分器的距离场重建。初始原始矿体也计作一次实际目标调用；上游采样器再次评初始距离场时也计一次，不隐藏重复调用。
- 基线每次最多 1000 次目标调用；另有求解墙钟上限，适配器预留 10 秒返回矿体。记录实际调用次数及停止原因；若调用上限先触发，不称为完全使用了 120 秒。
- LDM 内部可以自行写损失、近似损失或闭式优化，无法事后可靠恢复全部内部调用数。因此**这一轨道匹配的是求解资源上限，不是目标函数调用数**。未观察到的内部调用数记录为未知。
- 每个输出矿体由无候选代码挂载的原独立 scorer 评分，报告各 seed、均值和标准差、CPU/墙钟资源、失败数。不能挑最好 seed 对平均基线。

### B. 作者配置复现：`paper-1000-v2`

- 两个 case，seeds=47/48/49，原论文 sampler 每条链 1000 个 loss 调用（含初始），温度分别 3/20。
- 保留原距离场损失作为采样接受准则，输出同时保存原损失曲线和独立评分结果，不能把两种损失混在一起。
- 每条链资源保护上限 3600 秒、2 CPU、4 GiB；若提前耗尽时间，明确报告实际调用次数，不宣称完成 1000 步。
- 该轨道是原方法复现，**不直接按 1000 步与 LDM 外层 81 次评分排名**。

## 公平性边界

一次 LDM 正式评分执行整段反演算法，可能包含很多内部目标计算；一次 MCMC loss 调用通常只评价一个矿体。把两者都叫一次评估并直接对齐数字，会给算法生成方法隐含优势。

A 轨道只回答“已设计好的算法，在同等求解资源下谁拟合得更好”。LDM 的先前代码设计、agent 工具探索、未选中的提案、接口测试、GP 和模型调用都不是免费成本：历史预算及耗时单列，**不据此声称端到端算法发现成本优于 MCMC**。若要比较端到端效率，需要另行匹配并审计设计阶段的总计算/API 成本；现有历史无法补出精确内部 oracle 次数。

所有损失仍是对已知测量的拟合结果，不是隐藏测点泛化或真实矿体精度；低损失不等于不确定性刻画更好。

## 必须披露的适配

- 原代码无接触点时对空数组取均值产生 NaN。适配器使用原数学式的稳定 `logaddexp`，空接触约束为零；原文件未改写。真实初始 case 原始损失与当前实现一致：405.0795810830953、1248.8385761871953。
- 原 GSTools SRF 未固定 realization seed；复用 package 的 `ReproducibleGaussianField`，将 realization 绑定到 NumPy seed，保持 Gaussian 分布与参数范围。
- 原 sampler 在扰动后没有零等值面时会直接退出。扩展预算的固定接口检查暴露了这个问题；适配器仅对此特定 ValueError 保持原状态，下一次目标计算仍计预算，并记录 invalid_proposals。不能将此健壮化版本称为逐比特原样执行。首次失败批次、启动记录及源码快照均保留；最终版本在两个 case 的正常调用上限（1000）/短时间上限（30 秒）检查均成功。
- 使用连续 C-order 数组，避免本环境 scikit-fmm 对 Fortran stride 的已知问题。
- 原方法的内部距离场损失与输出再重建后的独立损失不保证完全相等；A 轨道统一目标，B 轨道原样保留并分别报告。
- 两组小预算 smoke 各六个基线组合均通过固定接口检查和独立评分，且实际 loss 调用数严格等于 3。最初 NaN 的失败 smoke 独立保留。
