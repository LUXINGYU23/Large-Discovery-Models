## 公平性边界

一次 LDM 正式评分执行整段反演算法，可能包含很多内部目标计算；一次 MCMC loss 调用通常只评价一个矿体。把两者都叫一次评估并直接对齐数字，会给算法生成方法隐含优势。

A 轨道只回答“已设计好的算法，在同等求解资源下谁拟合得更好”。LDM 的先前代码设计、agent 工具探索、未选中的提案、接口测试、GP 和模型调用都不是免费成本：历史预算及耗时单列，**不据此声称端到端算法发现成本优于 MCMC**。若要比较端到端效率，需要另行匹配并审计设计阶段的总计算/API 成本；现有历史无法补出精确内部 oracle 次数。

所有损失仍是对已知测量的拟合结果，不是隐藏测点泛化或真实矿体精度；低损失不等于不确定性刻画更好。

## 必须披露的适配

- 原代码无接触点时对空数组取均值产生 NaN。适配器使用原数学式的稳定 `logaddexp`，空接触约束为零；原文件未改写。真实初始 case 原始损失与当前实现一致：405.0795810830953、1248.8385761871953。
- 原 GSTools SRF 未固定 realization seed；复用 package 的 `ReproducibleGaussianField`，将 realization 绑定到 NumPy seed，保持 Gaussian 分布与参数范围。
- 原 sampler 在扰动后没有零等值面时会直接退出。扩展预算的固定接口检查暴露了这个问题；适配器仅对此特定 ValueError 保持原状态，下一次目标计算仍计预算，并记录 invalid_proposals。不能将此健壮化版本称为逐比特原样执行。首次失败批次、启动记录及源码快照均保留；最终版本在两个 case 的正常调用上限（1000）/短时间上限（30 秒）检查均成功。
- 使用连续 C-order 数组，避免本环境 scikit-fmm 对 Fortran stride 的已知问题。
- 原方法的内部距离场损失与输出再重建后的独立损失不保证完全相等；A 轨道统一目标，B 轨道原样保留并分别报告。
- 两组小预算 smoke 各六个基线组合均通过固定接口检查和独立评分，且实际 loss 调用数严格等于 3。最初 NaN 的失败 smoke 独立保留。
