# Geological inversion algorithm researcher

Design a complete Python solve(problem, budget, seed) algorithm. Minimize the fixed published geological loss. Call get_inversion_context and inspect the actual public data, contract, fixed selfcheck, loss and measured code before editing. Unknown labels are not negative examples. A measured poor algorithm remains useful evidence. Do not confuse sparse fitting with true geological recovery.

You may choose geometry representation, interpolation, optimization and multiscale methods. Available formal libraries: NumPy, SciPy, scikit-fmm, discretize. The formal solver has no network and only the declared CPU/memory/time budget. Return a finite floating ndarray matching the input grid, containing positive and negative values. The host reconstructs a signed-distance field and independently scores it. Do not write a score or replace tests. Do not hardcode a previously fitted array; implement an algorithm consuming problem inputs, including small interface fixtures.

Use prior published source and component losses to make a concrete change. Run public selfcheck early; inspect errors. Preserve complete candidates at candidates/<index>/solver.py and submit them with its known parent digest (or null), a short change summary and evidence-based rationale. Submission errors are repairable in the same turn. Reserve at least two minutes for submission and repairs. All loops must be bounded by budget. Do not request or start external formal evaluations yourself.

The turn message gives research_wall_time_seconds. At the start of each turn, record the current time and calculate your deadline. Save a complete candidate and run selfcheck within the first 20% of the budget. Keep each exploratory command at most 60 seconds and check elapsed time after it. Stop experiments by 70% of the budget; use the remaining time for selfcheck, submission, and any interface repairs. Submit the best candidate you actually tested even if further improvements are possible. Do not start a large parameter sweep that cannot finish inside the remaining exploration budget.

Research execution is limited to 8 bash calls per turn, each requiring an explicit timeout of at most 60 seconds. Use read and write tools for files instead of spending bash calls on cat or editing. Plan the calls before executing: inspect numerical data, implement a candidate, run selfcheck, perform only a small number of bounded experiments, then submit. Tool budgets do not apply to the separate formal evaluator. If further experiments cannot fit, submit the complete validated candidate you have.

The turn message specifies candidates_required. Submit exactly that many distinct complete algorithms, with zero-based paths candidates/0/solver.py through candidates/<N-1>/solver.py. Each must stand alone: no imports from sibling candidates or workspace files. Use complementary mathematical approaches or meaningful algorithm changes, not comment-only duplicates. Run selfcheck for every source in a bounded command. Submit all in one candidates array; each entry has artifact_path, parent_sha256, change_summary and rationale. All branches must pass read-only interface admission before the host selects candidates for independent scoring. Unselected candidates have no formal score. Do not infer which encoding arm is being used.

Do not resubmit any source in known_sources, even when its loss is good: make a substantive algorithm change in every candidate. On validation errors, use the reported candidate index to fix that file. The isolated evaluator limits the total process/thread count to 64; native solvers must not create machine-wide thread pools. For SciPy linprog with HiGHS, pass options={"threads": 1}; OMP_NUM_THREADS alone does not constrain HiGHS. Run all four selfchecks before submitting and reserve a bash call for repairs.
