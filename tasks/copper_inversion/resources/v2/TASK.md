# Copper v2: design one geological inversion algorithm

Implement `solve(problem, budget, seed)` returning a finite float32/float64 3D ndarray. One source must handle every public input and future unseen cases. Public case names contain no geological meaning. Missing data are unknown, not negative.

Read `cases.json`, load each case using `tasks.copper_inversion.v2.data.read_problem(path)`, and inspect `tasks/copper_inversion/v2/{contract,geometry,objective}.py`. Observations are physical-coordinate points, labels 0/1/contact 0.5, independent group IDs and measurement uncertainties. There is no initial model or hidden geometry in the input. Grid origin and anisotropic spacing vary.

Positive values mean the target unit. The scorer canonicalizes occupancy `field > 0`; amplitudes cannot move the canonical boundary. A positive voxel outside domain_mask or inside forbidden_mask is invalid. The scorer does not clip violations. Respect declared closed boundary shells and public hard priors. Do not impose a single component or closed geometry when the input does not require it. Empty outputs are legal where permitted, but are measured against the same hidden geometry as every other output.

All solvers share `objective.score(problem, field)` for measurement fitting and geological regularization. Contacts are separate from binary labels. The independent scorer applies this same objective to sealed confirmation measurements with the same public geological priors. If that loss is L, outer loss is L/(1+L), averaged within each geology parent, then equally across parents. Failed solves contribute one. The bounded transform is part of the fixed protocol; it prevents failed solves from disappearing and prevents unbounded numerical penalties. IoU is an auxiliary geometry diagnostic and never determines ranking or validation selection. Only aggregate training feedback is provided. You cannot query confirmation measurements or hidden truth from a solver or research tool. Design a reusable inversion algorithm; do not bake in models from these examples.

Formal per-case budget: 120 wall seconds, 2 CPUs, 4 GiB, 64 processes/threads, no network. Pilot budgets may be smaller and are passed explicitly in `budget`. Account for initialization and reserve serialization time. Do not execute the full training suite yourself. Do not launch external evaluations. Small public-fixture checks are allowed within research tool budgets.

Use `python selfcheck.py /workspace/candidates/0/solver.py` from this directory, for each requested candidate. These checks cover varied shapes, units, origin, contact counts and boundary masks. They check interface legality, not reconstruction quality. The controller checks the sealed candidate in a separate read-only container. Available solver libraries are NumPy, SciPy, scikit-fmm, discretize. The shared v2 public modules are also importable in the solver. Output only the model; candidate-written scores are ignored.
